# ForecastAgent 1.0.5 collection recovery

This release promotes the collection repairs audited on 55 prospective MiniBench
snapshots. It starts from immutable `v1.0.4`; analysis, context delivery, model
routing, probabilities and submission adapters retain that release's behavior.
The outer worker reports 1.0.5 while the evidence delivery protocol remains 1.0.4.

## Changes

- Bounded collection closure and actual interruption have distinct receipts.
- Closed observed leads can reach independent supplement without repeating the
  collector. Unknown or failed model receipts never grant that transition.
- Short issuer identifiers can route an existing final basic Extract allowance.
  The reservation is durable across restarts and preserves explicit deferrals.
- All-failed recovery reads report gaps rather than successful acquisition.
- Empty exported packages cannot start analysis. The official worker records
  `provider_blocked` with the preserved material gap once, without futile retries.
- Resource reports distinguish unknown HTTP status, transport error types and
  reserved fetch operations from confirmed HTTP requests.

## Budgets and data

Per-task limits remain three Tavily basic searches, one logical Exa search, eight
initial fetch operations, one basic Extract batch of up to five URLs and the
existing independent supplement limits. Exa transport failover on `main` remains
separate; a physical backup request never creates another logical search slot.
Old snapshots and provider journals are immutable. No resolution labels are used.

## Deployment and rollback

Pin the official worker checkout and module to `v1.0.5` and
`ForecastAgent.releases.v1_0_5`. Keep Super and Exa failover configuration unchanged.
Confirm no active worker and no old-version nonterminal task before switching.
Accepted forecasts, skipped records and delivery receipts are retained exactly.
Any incompatible inflight identity requires explicit migration or drainage.

Verification-only dispatch restores the exact checkpoint and checks fresh monitor
inventory without collection, models or submission. Roll back only at a clean
task boundary by restoring the `v1.0.4` tag and entrypoint; never reset budgets.

## Evidence limits

Offline replay validates 55 identical saved bundles, original file hashes,
reservations and absence of newly removed handoff routes. It establishes repair
behavior, not source relevance or forecast skill. Bounded live document and
Extract probes are stored separately from the prospective dataset. A blocked
publisher may remain blocked. A later resolution must be stored separately from
these acquisition snapshots.
