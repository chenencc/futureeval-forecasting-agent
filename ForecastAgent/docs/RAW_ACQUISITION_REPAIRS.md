# Raw acquisition routing and provider recovery

Explicit question months and resolution date boundaries produce a calendar
routing hint. Candidate URL/title and publisher date hints affect acquisition priority; they do
not establish event dates, truth, publication availability, or complete recall.
Unknown dates remain eligible. Older and later context is retained. No current
capture cutoff is introduced. Ambiguous periods have no inferred window.

Long link-heavy navigation with loading/search controls and no substantial
prose is marked as a possible shell. This is a conservative extraction gap,
not a claim that an official document or event does not exist. Original
responses remain preserved. A failed Basic Extract body also remains in the
failed-capture inventory and consumes its existing allowance.

Canonical URLs remain legacy comparison keys so resumed task ledgers retain
their identity and consumed budgets. Free HTTP reads and Basic Extract resolve
accepted comparison keys to the exact original catalog URL, preserving opaque
query paths, repeated parameters and publisher encoding. A previously altered
snapshot cannot reconstruct an unknown original URL; do not invent a repair.

The manually dispatched `Forecast provider health probe` workflow makes one
physical Ultra request with a 256-token output cap and one acknowledgement
tool. It has no search credentials, no task state, no forecasting tools and no
retry loop. Its artifact reports both HTTP status and any embedded provider
error. Only an actual valid tool acknowledgement counts as healthy. A single
successful probe does not prove sustained availability or authorize a campaign
budget reset.
