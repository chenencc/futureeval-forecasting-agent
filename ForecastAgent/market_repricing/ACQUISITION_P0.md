# Acquisition P0 candidate

This development candidate keeps the selected `c17c1ec` engine, Super collection
model, Mercury forecasting sources and analysis prompts unchanged. Production
still selects its independent immutable version. The candidate is not deployed.

## Three changes

1. **Body roles and data coverage.** Every market admission records a body role,
   observed dates, declared table rows and truncation. Sharing intents, access
   interstitials and navigation are not original event evidence. A legitimate
   short official notice remains readable. Readability never proves target
   coverage, source credibility or truth.
2. **Bounded spreadsheet originals.** A saved public Google Sheets identity can
   produce one explicitly bound CSV export candidate. It uses the existing
   supplemental HTTP allowance, never a hidden request. Full original bytes are
   preserved. A bounded row view retains original row coordinates and explicitly
   reports omitted rows. The first six and last two hundred physical rows are
   not guaranteed to be the latest observations. Ambiguous date order remains
   unknown. Export401/authentication failure is preserved without another route.
3. **Cross-stage source reuse.** Exact/final URL matches and an observed MND
   English PLA bulletin document-ID contract can reuse a saved readable original.
   Capture clocks do not change. Arbitrary path case and query parameters remain
   significant. A failed/blocked bulletin alias cannot satisfy the saved-source
   contract. Reuse records identify the parent and content hash.

The native collection adapter, independent supplement and final forecast
admission use the same quality contract. New records stay separate from frozen
parents; model explanations and graphs do not become original evidence.

## Compatibility

The original budget compatibility manifest remains unchanged. A separate
`capture_stage_candidate.json` declares the three changed/new capture files and
their legacy/new hashes. Analysis and search files still require their frozen
hashes. Started tasks must retain their exact capture identity; a new candidate
must not reopen terminal tasks or silently replace active stage implementations.

## Local validation

```text
python -m ForecastAgent.market_repricing.experiments.acquisition_p0 \
  --engine ENGINE_CHECKOUT --output SHADOW_DIRECTORY
```

The offline gate replays18market material vintages and one official ADIZ packet,
checks original hashes and new body exclusions, and runs focused negative tests.
`--live` uses three frozen, still-open market identities in a separate shadow
ledger. Its ceiling is45model POSTs and12search-provider POSTs; native per-task
search/capture limits remain active. It does not run final forecasting, submit,
trade, replace production records or reset production budgets.

admission retains10/9/10distinct readable bodies. Two WhatsApp share controls
discovered by this pilot were subsequently excluded using the saved snapshots,
with no additional model requests. This is a functional acquisition trial, not
a held-out forecast benchmark or live controlled A/B.
