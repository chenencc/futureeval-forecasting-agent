# Acquisition P0 candidate

This development candidate keeps the selected `c17c1ec` engine, Super collection
model, Mercury forecasting sources and analysis prompts unchanged. Production
selects its independent immutable version; promotion requires recorded Linux
integration and actual saved-state preservation gates.

## Three changes

1. **Body roles and data coverage.** Every market admission records a body role,
   observed dates, declared table rows and truncation. Sharing intents, access
   interstitials and navigation are not original event evidence. A legitimate
   short official notice remains readable. Readability never proves target
   coverage, source credibility or truth.
2. **Bounded spreadsheet originals.** A saved public Google Sheets identity can
   produce one explicitly bound CSV export candidate. It uses the existing
   supplemental HTTP allowance, never a hidden request. Full original bytes are
   preserved. A bounded row view retains original row coordinates and explicitly
   reports omitted rows. The first six and last two hundred physical rows are
   not guaranteed to be the latest observations. Ambiguous date order remains
   unknown. Export401/authentication failure is preserved without another route.
3. **Cross-stage source reuse.** Exact/final URL matches and an observed MND
   English PLA bulletin document-ID contract can reuse a saved readable original.
   Capture clocks do not change. Arbitrary path case and query parameters remain
   significant. A failed/blocked bulletin alias cannot satisfy the saved-source
   contract. Reuse records identify the parent and content hash.

The native collection adapter, independent supplement and final forecast
admission use the same quality contract. New records stay separate from frozen
parents; model explanations and graphs do not become original evidence.

## Compatibility

The original budget compatibility manifest remains unchanged. A separate
`capture_stage_candidate.json` declares the three changed/new capture files and
their legacy/new hashes. Analysis and search files still require their frozen
hashes. Started tasks must retain their exact capture identity; a new candidate
must not reopen terminal tasks or silently replace active stage implementations.

  --engine ENGINE_CHECKOUT --output SHADOW_DIRECTORY

`--live` uses three frozen, still-open market identities in a separate shadow
ledger. Its ceiling is45model POSTs and12search-provider POSTs; native per-task
search/capture limits remain active. It does not run final forecasting, submit,

## Public table gap follow-up

Saved Google public worksheet metadata can expose additional tabs in the same
workbook. The candidate reads literal JSON metadata only, never executes page
JavaScript or guesses worksheet IDs. Each public view lead carries its observed
tab ID, parent original hash and parent capture time. Existing capture limits
remain active and only one workbook navigation layer is admitted.

A workbook CSV export returning401 prevents automatic attempts against another
tab's export endpoint. Ordinary observed public views remain separate sources.
Authentication, removed-source and rate-limit failures are retained with typed
reasons rather than silently cycling through browser retries.

The offline public-cell reader binds each rendered row to its actual worksheet
row ID and each cell to its column coordinate. Horizontal and vertical merges
retain their spans. The projection has1000-row and100000-character ceilings;
omissions remain explicit. Original bytes, hashes and capture clocks stay intact.
Rendered declared grid extent is not complete target-series certification. Month
labels retain month precision; an in-progress month is not a final observation.

The October14follow-up performed two public GETs and no model/search calls. The
FAQ exposed70rendered rows and the monthly category table75, extending to an
October2026label. Both match the requested tab and declared grid dimensions.
The original Daily Totals view still exposes only100of2227declared rows. Its
full daily series and denied CSV export remain gaps. The third-party FAQ also
distinguishes de facto ADIZ activity from median-line crossings; neither its
authority nor metric equivalence is inferred from readability.

New originals and coordinate views are preserved as a later independent
supplement, with immutable parent linkage and packet-object verification. The
171market tests,11pinned-engine tests and19frozen-input regression are offline.
These checks validate transport, parsing and preservation; they do not measure
forecast accuracy or certify the three pilot questions' semantic completeness.

The public-sheet runtime tests run only after activating the exact selected
engine, which provides the saved-source parser. The standalone163sidecar tests
remain independent. Linux promotion includes11sheet-runtime tests, the other
engine integration gates and a read-only production checkpoint restoration.

capability boundary and independent Metaculus/market promotion requirements.
