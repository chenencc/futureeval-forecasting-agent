# P0 saved-evidence analysis experiment

This optional strategy replays unchanged original acquisition and prior independent
repair overlays. No new search, body capture, screening or forecast submission is
performed. Production remains pinned to release 1.0.1.

## Three changes

1. **Quoted rule contract.** Preserve the complete original question and fine print.
   Record exact field offsets for timing, actor/action, observation and exception
   clauses. Date mentions, unit terms and release-window syntax are lexical cues;
   unresolved semantics remain explicit. No resolving answer is read or inferred
   by the compiler. Declared primary links are leads, not automatically verified facts.
2. **Directed reading.** Rank saved original spans using low-frequency entity and
   metric terms, target months, date/value/unit/table indicators, declared primary
   sources and publication-vintage cues. Reserve context for direct measurements,
   then source coverage and neighboring original spans. Span text is bounded to
   1,800 serialized bytes so multilingual headings do not consume disproportionate
   request space. Bind selected measurements to their original source heading.
   Retain every saved character in the local library, hashes and exact
   offsets; all first-pass evidence remains available in the second request.
3. **Program coverage routing.** Record missing lexical indicators and whether
   unseen saved text can fill them. Audit release-versus-observation ambiguity even
   when model diagnostics claim sufficient evidence. These indicators cannot
   establish semantic truth and never directly modify probabilities.

## Budgets and comparison

First and second request limits remain 22,000 and 28,000 bytes. Each task receives
at most two free Mercury HTTP attempts in its new experimental journal. A second
read requires diagnostic or program reasons and additional exact source spans.
Unlike the legacy gate, a short new passage can qualify; an arbitrary minimum
character count is not proof of informational value. Second-request failure retains
the validated first decision. Resuming never replenishes attempts.

Nonbinary grids, interpolation and probability clipping are unchanged. Date cases
without official metadata retain research-only distributions. Calibration and model
fusion are not added in this experiment.

`analysis_p0_forty.yaml` runs the same 20 binary and 20 nonbinary questions in eight
sequential batches. The historical Mercury baselines are runs 37022482053 and
37031590213. Baseline forecasts are saved separately and never enter inference.
Changing a contract, input, implementation or decision request refuses resume.

The cohort is a development regression set containing previously inspected errors.
Repeated inference varies, saved evidence may reveal outcomes, and improvement on
these questions does not establish independent or prospective forecasting ability.
