# Competition collection enhancement deployment

The production competition worker selects immutable `v1.0.5-capture.1` at
`f06d50300a6779688fe7c1167d56e01a3434d053`. It checks the tag, commit and frozen
release manifest before using any provider. Source and tests are maintained on
`codex/metaculus-eager-capture`, independently from market deployment.

The enhancement reads at most two accepted source URLs immediately after each
Tavily/Exa discovery call, within the existing eight native fetch reservations.
Two slots remain reserved for later Agent choices. Source-shape annotations
retain short notices, previews and uncertain markup; explicit empty navigation
shells stay in raw storage but do not count as readable analysis bodies.
Content-addressed capture objects retain original bytes, search records, source
clocks, parent hashes and observed one-hop document-link provenance.

The release's Mercury analysis, conditional rereading, typed distributions,
0.02–0.98 clipping and receipt-based duplicate-submission protection are
unchanged. Tavily remains basic with at most three lifetime searches; Exa remains
one. Browser, Extract, supplement and model caps are unchanged. Market versions,
market credentials, admission rules and price heads stay independent.

Acceptance: 130 offline fault/recovery/format/delivery checks and Linux run
38509110474 passed. Five frozen Metaculus MiniBench material replays retained
all 15 control-readable bodies and admitted two additional saved bodies, using
the same search leads and native fetch allowance. No live search/model calls
were used in this comparison. It is an acquisition-engineering check; semantic
coverage and forecast skill remain unmeasured. Old snapshots were not replaced.

Deployment requires a zero-pending old collection preflight. Verification-only
worker execution checks exact restored state and runtime without provider
search/model calls or forecast submission. Ordinary cron-driven admissions use
the new collector. Existing accepted forecasts stay terminal.

Rollback changes only the competition workflow's release pins to
`v1.0.5-recovery.2` / `bf9a425f8425c9a685bd3b24979935b7cfe04981`, removes the new
capture-specific runtime assertions and retains all state. If tasks are active,
first preserve their exact release/input/provider identities; never reset their
quotas or silently reopen accepted tasks.
