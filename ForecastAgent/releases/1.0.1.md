# ForecastAgent 1.0.1

The official competition worker checks out the immutable `v1.0.1` tag. Its new-question pipeline is original acquisition, independent supplemental repair, Mercury original-evidence conditional rereading, and atomic forecast/private-comment delivery with platform readback.

Acquisition retains the existing collection agent, Ultra primary and automatic Super service-failure fallback. Each task preserves its lifetime three Tavily basic searches, one Exa search, eight acquisition fetches and existing model reservations. Supplemental repair retains its separate bounded journal and exact parent hashes; it does not run models or search providers.

Mercury independently reads exact saved bodies. It first receives at most 22,000 request bytes. A second request is allowed only for diagnostic gaps with at least 900 new original characters, at most 28,000 request bytes, retaining the first evidence. The final successful Mercury response supplies the forecast directly, without averaging with an additional reasoning forecast. A failed reread preserves the validated first response. If Mercury's first call is unavailable, the previously authorized reasoning-only fallback uses its separate durable ledger and does not attempt another Mercury call. Integrity failures never trigger fallback or an invented default.

Binary forecasts use the event probability. Multiple choice forecasts use exact current platform options and a bounded simplex. Numeric, discrete and date forecasts use coarse mutually exclusive outcome bins aligned with the authoritative platform CDF grid, then deterministic interpolation and platform standardization. Date boundaries are rendered as UTC dates. Missing metadata blocks delivery rather than inventing a research range. Coarse bins limit resolution and do not establish calibration.

The existing 0.02–0.98 policy applies to binary probabilities, feasible category vectors and interior CDF probabilities. Closed CDF endpoints retain platform-required zero or one. Existing accepted forecasts, frozen candidates, delivery reservations and quotas are preserved. New pending analyses use a separate `mercury-v1.0.1` journal. Reconciliation of an earlier submission retains its exact earlier payload and private comment.

External cron dispatches the existing official question monitor. Successful monitor runs trigger the serialized official worker, which processes at most five pending questions in deadline order. Later polls continue the remaining queue. The worker rechecks status, rules, deadline, bot permissions and authenticated own-forecast history before spending and before delivery. Unknown submissions are reconciled without blindly reposting.

Acceptance: offline tests cover all five supported types, exact live metadata, clipping, immutable decision replay, failed second-call preservation, provider-only fallback, seven-question five-plus-two queue draining, accepted/unknown receipt handling, and duplicate-spend prevention. Retrospective pilot metrics are diagnostic and are not evidence of live forecast calibration.
