# ForecastAgent 1.0.0

## Frozen baseline

The immutable `v1.0.0` tag identifies tested code commit
`7af994132ba3d8101d5257ed36bbfd883a292404`. Release documentation and deployment
planning may be maintained in later commits without moving this tag.

This release preserves raw acquisition, supplemental acquisition and the v8
binary analysis protocol. It is a research baseline, not an enabled end-to-end
competition deployment. The scheduled monitor and collector remain read-only.

## Analysis policy

- Primary: `nvidia/nemotron-3-ultra-550b-a55b:free`.
- Fallback: `nvidia/nemotron-3-super-120b-a12b:free`, after two consecutive
  service failures, sticky for the dispatch. Account quota, credential and
  invalid-request failures do not activate fallback.
- Three physical HTTP attempts per reasoning backend per task, at most two
  backends, eight local saved-body reads, and one Mercury request.
- Probability adapter: `inception/mercury-decide:free`.
- Preserve reasoning probability, Mercury probability, arithmetic mean and
  disagreement separately. Both routes share qualitative analysis; they are
  not independent forecasts. No empirical calibration is fitted.
- A missing route remains missing. The explicit workflow default of 0.5 is not
  a model forecast and must not be automatically submitted to a tournament.
- Citations, original response journals, evidence identities and consumed
  budgets survive interruption. Provisional numeric recovery remains flagged.

Acquisition preserves the existing per-task maximum of three Tavily basic
search attempts and one Exa search attempt, including failed reservations.
Existing collection journals are never replenished by this release.

## Known limitations

1. Analysis currently produces binary probabilities only. Numeric, discrete,
   multiple-choice and grouped-question submission adapters are not validated.
2. The monitor queues acquisition, not supplementation, analysis or submission.
   Capturing a question never proves that Metaculus accepted a prediction.
3. The analysis workflow expects a frozen historical campaign; live collection
   artifacts require a dedicated input adapter with deadline metadata.
4. Quality flags can treat the string `none` as a gap and do not represent
   alternative sufficient conditions correctly. These known defects are
   preserved in the baseline and require a separately versioned patch.
5. Automatic forecast eligibility remains disabled. Submission permission,
   payload correctness and server-side readback have not been certified for
   this analysis chain.
6. GitHub schedule delivery is best effort. Durable state must be retained
   independently of the 90-day Actions artifact expiry.
7. Provider aliases, available models and external Actions may change. The
   Git tag freezes repository code, not external services or model weights.

See `ForecastAgent/docs/COMPETITION_LAUNCH.md` on the maintained branch for
the production readiness plan. Future fixes must use a new version; never
move `v1.0.0` or rewrite its diagnostic outputs.
